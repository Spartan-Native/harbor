Spartan Native · sample app

One backup app. Native everywhere.

Harbor Backup is a real, multi-page Angular app built from stock spartan/ui components and the Spartan Native packages. The same code looks at home on Windows, macOS, GNOME, KDE and ChromeOS, in the browser and as a desktop app, and follows the user's accent, light/dark and contrast live.

Seven skins · light & dark Browser · PWA · Wails MIT
Try it in your browser View the source
app.config.ts 
// The only line that knows where Harbor runs.
provideSpartanNative({
  host: isWails() ? wailsHost() : webHost(),
});
terminal 
git clone https://github.com/Spartan-Native/harbor
cd harbor && npm install
npm start

One app · seven skins

The same window. Unchanged.

No per-platform templates. The skin draws geometry, materials and states; the host adapter brings the user's accent and settings. Switch skins live from the dev bar in the demo.

Pages

A real app, not a component gallery.

Five pages share one store, so a change on one shows on the others: a new destination appears in Overview's storage card, a restore is added to recent activity.

Overview

The running backup with progress and pause, the schedule switches, storage per destination, a backup size chart for the last seven days and recent activity with status badges.

Schedules

A table with desktop selection (click, Shift/Ctrl/⌘-click, arrow keys), a right-click menu, an upcoming runs calendar, and a modal sheet to add or edit a schedule.

Destinations

NAS, USB, cloud and SFTP as cards or a list, filtered by kind. Verify, rename and remove, a coach mark, and a multi-step add form with validation.

Restore files

Browse a snapshot in resizable panes: folders, a selectable file table, search, breadcrumb and an inspector. Restore with keep both, replace or skip, then watch the progress.

Settings

General, Backups, Notifications, Advanced and About, laid out the way each OS lays out its settings, with shortcuts in the platform's notation and per-OS rows.

Window chrome

Title bar and window controls per OS, a status bar and a command bar from @spartan-native/desktop-ui. Installed as a PWA, it draws into the title-bar overlay.

Browser & desktop

Three ways to run. No UI changes.

The host adapter is picked at startup. Everything else talks to @spartan-native/theme only.

Browser tab

webHost() reads light/dark, contrast, transparency, text size and window focus from the browser, live. Harbor draws the full mock window on a wallpaper, with a dev bar to switch skins.

Installed PWA

A manifest, maskable icons and a service worker for offline use. Installed, Harbor fills the window and can draw its own title bar in the window-controls overlay, and Chromium can hand it the real accent.

Wails desktop app

wailsHost() and the Go service from host-wails read the accent and settings from the OS itself, and drive the real window, menus and file dialogs.

Run it

Clone, install, start.

Node 24.15+ or 26 and npm 11. The packages come from npmjs.org: no token, no registry setup. The desktop shell also needs Go 1.26+ and the Wails v3 platform prerequisites.

In the browser

terminal 
npm install
npm start          # http://localhost:4200

As a desktop app

terminal 
npm run start:desktop:wails
# build only:
npm run build:desktop:wails

Storybook & tests

terminal 
npm test           # unit tests
npm run storybook  # one story per page
npm run test:visual
Why it exists

The end-to-end test for Spartan Native.

Every package and host adapter has to carry Harbor before it ships. If something only works in a story, Harbor finds out.

◧

Stock components

spartan/ui helm components, committed unmodified. The theme restyles them from CSS only.

⇄

Host-agnostic

One line in app.config.ts picks the host. No UI code knows the runtime.

▦

Every page, every skin

A visual test screenshots each page on all seven skins, in light and dark.

⏱

Stable demo data

"Today" is fixed at Thu 12 March 2026, 09:12, so screenshots never drift.
